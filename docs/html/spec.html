00 · Foundations

Executive summary & roadmap

What we're shipping, the philosophy underneath it, and the phasing that lets one engineer ship MVP and a team scale into multiplayer without re-architecting.

The product, in one sentence

A pocketable 30-second duel — the player picks, the CPU picks back, the result lands instantly — wrapped in a theme engine that turns the same gameplay into four distinct emotional experiences and unlocks theme packs as the primary monetization surface.

Principles

  • The duel is the product. Onboarding, monetization, settings — all serve the 2-second commit-lock-reveal arc.
  • One engine, many skins. Themes are interchangeable, runtime-swappable, and never fork business logic.
  • Replay over depth. If a feature adds friction to the next tap, it doesn't ship until Phase 2.
  • Multiplayer-shaped from day one. Local state mirrors the eventual server schema so PvP is an integration, not a rewrite.
  • Monetize the desire to belong, not the desire to play. Ads/IAP touch cosmetics & convenience, never the core loop.

Navigation model

  • Home is the root. Returning from any subscreen pops back to Home.
  • Play is a push (not modal) so the duel can keep its own back-stack of pause/result states.
  • Settings / Themes / History / Store are pushes from Home.
  • Reset confirm · Ad reward · Purchase confirm · Pause are modal bottom-sheets.
  • There is no bottom-tab bar in MVP — it adds chrome the duel doesn't earn yet. Tabs appear in Phase 2 alongside Profile.
DecisionDon't ship tabs in MVP. The bottom of the screen is the duel's. Use a top app-bar for navigation and a single FAB-equivalent "Play" CTA on Home.

03 · Foundations

Game state machine

One state machine drives every duel — vs CPU, pass-and-play, async, ranked. The transitions are identical; only the I/O source for the CPU/opponent's pick differs.

States

Transition rules

From → ToTriggerGuardSide effects
idle → choice_selectedplayer taps R / P / Snot within debounce window (250ms)haptic tap; sound ui_tap
choice_selected → lockedauto, 80ms after choice—haptic lock; sound lock_thud; analytics choice_selected
locked → cpu_thinkingauto—request CPU move (or opponent move in PvP)
cpu_thinking → revealCPU move resolved · min 400ms / max 900msapp foreground; not pausedsound shuffle_stop
reveal → win/lose/tieauto, after 180ms hold—compute outcome; haptic per outcome; sound per outcome; analytics round_*
* → replay (idle)player taps any picker buttonnot in pauseincrement round; persist last to history; reset transient state
* → pauseapp backgrounded · or user opens menu—freeze timer; mute sounds
* → quituser confirms exit—save partial state; pop to Home

Edge cases

  • Rapid repeated taps — debounce 250ms on picker; second tap within window is ignored, no jitter.
  • Background during anticipation — pause; on resume, restart the CPU-thinking timer from where it paused (don't shortcut to reveal).
  • App killed mid-round — round is not persisted (only complete rounds enter history). Resuming opens Home, not Play.
  • Disconnect mid-PvP (Phase 3) — 15s grace; reconnect lands back into cpu_thinking with a "reconnecting" overlay. Past 15s, opponent forfeits the round.
  • Clock drift in async PvP — server is authoritative for outcomes; client renders the reveal animation on receipt.

Theme interface

Every theme is a ThemePack — a single object that bundles tokens, icons, sounds, haptics, and animation curves. The whole runtime reads from the currently-installed pack; no theme branching exists outside this object.

abstract class ThemePack {
  String get id;            // 'premium_minimal' | 'arena' | 'futuristic' | 'tactile'
  String get displayName;
  GameTheme get theme;     // colors, typography, radii, shadows
  IconPack get icons;
  SoundPack get sounds;
  HapticProfile get haptics;
  AnimationProfile get motion;
  Locale? get italicFallbackLocale; // null = use display italic everywhere
  bool get isFreemium;     // false for premium-only packs
}

07 · Implementation

Per-theme refinements

Every concept's identified weakness, paired with the concrete fix that lands in v1.0. Themes are kept distinct — fixes never make them converge.

Concept 1 — Premium Minimal

Weakness called out: wins don't celebrate; reads "cold" to lapsed casual-game players.

Fix:

  1. Add a single warm moment on reveal: the winning icon scales 1.0 → 1.08 → 1.0 over 360ms (back-ease), with the accent paint settling into it. Loser glyph nudges away by 4px.
  2. Streak indicator: a small italic "+2 in a row" tag appears below the verdict only when streak ≥ 2. Disappears on any loss/tie.
  3. Sound: a single, tasteful "page-turn" SFX on reveal (no chime); haptic HapticPattern.success on win.
  4. Increase the win color saturation by 8% (still warm clay, just enough to register as a state change in periphery).

Concept 2 — Competitive Arena

Weakness called out: niche esports aesthetic; can read as "kids gaming"; may push away the calm player.

Fix:

  1. Soften the stamp typography by ~15% (from 32px ExtraBold to 28px Bold). The diagonal clip remains; the volume comes down.
  2. Replace the flame 🔥 emoji on the streak chip with the streak count in mono + a thin underline accent. Reads as a stat, not a kid-game flair.
  3. Reduce hash-pattern opacity on the win-half from 0.16 → 0.10. Keeps the kinetic feel without shouting.
  4. Drop the "▌" leading-bar glyph from the onboarding CTA. Reserve it for in-game HUD.
  5. Add a "calm" reveal-speed setting in Settings (the speed knob is already there). When set to "slow", the stamp fades in over 320ms instead of snapping.

Concept 3 — Modern Futuristic

Weakness called out: accessibility — glow + low-contrast HUD; readability fatigue; aesthetic dates fastest.

Fix:

  1. Contrast pass. Bump --inkSoft from rgba(232,246,255,0.62) to rgba(232,246,255,0.78); bump --inkMuted from 0.38 to 0.55. Verified against WCAG AA at 14px+.
  2. Glow ceiling. Setting "Glow intensity" default changes from NORMAL to LOW. Power users opt up.
  3. Mono fatigue. Replace the "// CAUTION" / "▌ INIT" mono labels in non-system contexts with sentence-case sans. Mono stays for actual HUD readouts (round number, timestamps).
  4. Reduce magenta. Limit magenta to destructive states (reset, defeat). Onboarding, history badges, settings — all cyan only.
  5. "Monochrome" colour profile in Settings: collapses cyan + magenta to a single warm-white. Functional accessibility option; also a paid theme variant.

Concept 4 — Tactile Premium

Weakness called out: tactile interaction needs polish; onboarding clarity; icon language consistency; anticipation feedback.

Fix:

  1. Card flip primitive. A real RotationTransition on the Y axis, 280ms, easeInOutCubic. CPU card flips at reveal in both directions (face-down → face-up). 60fps on Impeller — verified.
  2. Anticipation feedback. CPU card pulses (1.0 → 1.02 scale) every 480ms during cpu_thinking. Three pulses max; if reveal takes longer, the card holds.
  3. Onboarding clarity. Add a tiny working "demo round" on step 1 — auto-plays Paper-beats-Rock in 1.2s. The player sees the loop before reading about it.
  4. Icon language unity. All RPS icons rendered at the same optical weight (verified against §11). Card corners pip uses the lowercase italic monogram; never a numeral.
  5. Press feedback. Picker cards translate 2px down + drop their shadow on press (40ms easeOut). The card feels pressed, not tapped.
Cross-cuttingAll four themes inherit the same accessibility opt-ins: Reduce motion (drops celebrate and reveal overshoot), Increase contrast (bumps muted/faint tokens by ≥15%), and Larger text (clamps typography at 1.3× without breaking layouts thanks to the spacing scale).

11 · Feel

Iconography

Real, recognisable objects. The three game icons + the small supporting set are drawn at one canonical weight and re-coloured by theme.

Rock · Paper · Scissors

Drawn as objects, not gestures — universally readable across en/tr/es without the hand-gesture ambiguity (the same fist can mean different things across cultures).

  • Rock — an irregular boulder with two faint facet lines. Asymmetric on purpose; a circle would read as a ball.
  • Paper — a sheet with a folded top-right corner and three content lines. The fold detail is the only thing that distinguishes "paper" from "card".
  • Scissors — classic shears: two crossing blades through a central pivot, two finger rings. Unmistakable at 16px.

Drawing rules

  • 32×32 viewBox source; renders 14–120px without artefacts.
  • Solid + outline variants; outline stroke width 2 at 32px, scaling to 1.5 at 16px.
  • No theme draws its own R/P/S — they all consume the shared IconPack primitives and re-tint.
  • Achievements ship as a parallel collection drawn in the same style; not bundled per-theme.
12 · Product

Multiplayer-ready UX

Designed in MVP, dormant until Phase 3. The state machine and screen vocabulary already support PvP; the network layer is the only thing missing.

Modes (Phase 3)

  1. Quick match — anonymous queue, ELO-bracketed, 30s max wait, falls back to "vs CPU" with a banner if no match found.
  2. Friend match — share invite link or 6-char code; private, persistent.
  3. Async match — turn-by-mail; the picked move is sent, opponent has 24h. Push notification on opponent's reveal.
  4. Ranked — quick-match but with SR (skill rating); season-based; placement matches in first 10.

Match lifecycle

matchmaking → lobby (both ready?) → match_active (best-of-N) → match_result → rematch?

   ├──[5s cancel grace]
   ├──[opponent leaves] → forfeit → SR adjustment
   └──[disconnect]       → 15s grace → reconnect | forfeit

Disconnect & reconnect

  • During CPU/opponent thinking: "reconnecting…" pill at top of duel screen; FSM frozen.
  • 15s grace window; if past, opponent wins by forfeit. SR penalty is half the normal loss.
  • Async matches don't need reconnect — the move is already on the server.
  • Both players disconnect within grace: match is voided, no SR change.

Rematch UX

  • Reveal screen on the final round of a match offers Rematch + Leave.
  • If both tap rematch within 15s, the room persists; if only one taps, the other gets a "X wants a rematch" notification (Phase 3).
Server schema previewThe local Round data class is intentionally shaped like the eventual server document: { matchId, roundIdx, youMove, opponentMove, outcome, themeId, timestamp }. When PvP turns on, the local persistence layer becomes the offline-write-then-sync cache without a schema change.

Ad placement strategy

Two formats. Two placements each. Hard frequency caps. No banners — they'd live in the duel's bottom third and the duel needs that real estate.

Allowed formats

Interstitial

Full-screen. Skippable per platform rules. Shown between matches, never mid-duel.

Rewarded

Player-initiated. Unlocks theme / removes the next interstitial for 24h / gives a "double-streak" boost (Phase 2).

Placements

post-match interstitialInterstitialOnce per 4 rounds, never within 90sTriggered on tap to replay; never on reveal. Skip CTA visible from t=0.

remove-ads CTA—Surfaced after dismissing 3rd interstitialSoft prompt — not a popup, an inline card on Home.

Hard rules

  • No interstitial in the first 5 minutes of first session.
  • No interstitial during onboarding or theme select.
  • Reduced cap (1 per 10 rounds) until day-1 retention threshold reached.
  • Players with remove_ads entitlement see zero interstitials, ever. Rewarded ads remain available as opt-in.
Anti-pattern guardrailIf interstitial CTR drops below 0.5% in the first week, we cut frequency, not the duel. The duel is the product. Ads are scaffolding.

App Store readiness

Five screenshots, three languages, one positioning line. The store listing is the second part of the funnel — the first part is the icon.

Positioning

"A quiet, premium game of three. Pick rock, paper, or scissors. We pick one back. The winner shows itself in a heartbeat. Tap again."

One sentence. Not a tagline; the actual first line of the App Store description. Sets restraint as a feature, signals craft.

Screenshot strategy (5 per platform · same script across en/tr/es)

  1. Hero (reveal · win) — Tactile Premium theme, big "You win." in serif italic. Top of screen: localized tagline overlay.
  2. Anticipation — your card lifted, CPU face-down. Tagline: "The wait is the game."
  3. Four themes — small grid showing all four duel screens. Tagline: "Four directions. Pick yours."
  4. History — calm scrollable list. Tagline: "Every round, kept."
  5. Onboarding step 2 — three cards intro. Tagline: "Three icons. One heartbeat."

Conversion logic

  • First screenshot must read as not a kids' game in <1 second. The hero serif italic does this; the abstract glyph-tournament aesthetic of the other concepts does not.
  • Screenshots 2-4 establish depth and care; screenshot 5 closes the "is it for me?" question.
  • Localized taglines, not localized screenshots. The duel itself is language-free.

Onboarding conversion

The whole onboarding to first round must be under 14 seconds. Language + Theme are skippable (defaults: device locale, Tactile Premium). The 3-card intro is the only mandatory step; even that has a "Skip" affordance after 3s.
